## 二、设计方向

**视觉用 NarraLeaf，交互学 GitHub。**

视觉：
- 只用 `tokens.css` 里的颜色、圆角和字体，主色 #40a8c4。
- 编辑器类页面完全照 Studio 工作台的样子做。
- 控制台类页面做成安静、低饱和的 Linear 风格侧栏。
- 品牌：叶子 Logo + “NarraLeaf Team”。团队没有设置自己的 Logo 时，用 NarraLeaf 的叶子，不再用首字。

交互（GitHub / Primer 的模式）：
- **SelectPanel 替换所有原生 `<select>`**：带搜索框、选项带说明和勾选、可以多选、能用键盘操作、选中立即生效。用于选评审人、权限模板、角色、Webhook 事件、语言、待办类型、版本范围等。
- **ActionMenu（“⋯”菜单）**收纳每行的次要操作；危险操作放在菜单最下面并标红。账号表、成员表、历史行都这样改。
- **确认对话框分两级**：普通危险操作弹 Dialog 确认；不可逆操作（删除项目、停用账号）要输入名字才能确认，照 GitHub 的 Danger zone 做。把 `window.confirm` 换掉。
- **设置页**：左侧子导航 + 每个分区独立保存（Subhead + 说明 + 保存按钮），最底部放 Danger zone。项目设置和管理后台都按这个结构重排；子页面写进 URL。
- **Blankslate 空状态**：图标 + 标题 + 一句说明 + 一个主操作，例如“这个场景还没有内容 → 在 Studio 中编辑”。
- **相对时间**：显示“3 小时前”，鼠标悬停显示完整时间。哈希截短成 7 位等宽字体，可点击复制。
- **用户相关**：头像 + 名字随处一致；鼠标悬停名字时弹出资料卡（角色、所在项目）。
- **批注像 PR 评论**：浮层贴在被批注的行旁边，按线程显示，有头像。每条线程底部只有一个回复框，“新建批注”是另一个明确的入口。右上角放“解决 / 删除”图标；回复框支持 @ 自动补全。
- **反馈**：成功用 Toast（Flash）提示；错误用中文说明，原始信息折叠进“详情”。
- **标签页**：UnderlineNav 样式，标签上带计数，比如“评审 2”“历史 5”。
