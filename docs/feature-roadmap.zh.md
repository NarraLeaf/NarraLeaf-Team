# Team 新功能实施计划（2026-11-16）

来源：功能盘点和同类产品对比，以及缺陷检查（这一轮对话）。用户确认的范围：
- P0–P7 全部要做，另外修掉缺陷检查找到的问题。
- Team 和 Studio（`../NarraLeaf-Studio`）两边都做。
- **这次不做**：分支 / 草稿版本、AI 辅助。

守住的边界：
- D1：控制台不编辑项目内容。
- D2：服务端不解析项目文件。diff、质检、引用、统计都在网页端用 `@narraleaf/project-view` 读文件来算。
- 不做网页合并、不做 CI、不开放公开注册、不做完整 issue 系统。

每个阶段一个提交（Team 和 Studio 各一个），提交时逐个列出文件路径。Studio 里用户没提交的文件（`ServersTab.tsx`、`teamDeepLink.ts`、`teamDeepLink.test.ts`）一律不碰。

## 阶段 A：P0 已知短板 + 缺陷检查找到的问题

| 项 | 做法 | 改哪边 |
|---|---|---|
| 加载失败显示英文原话 | 读取失败统一走 `friendlyError`；项目不存在时显示 404 空状态页 | 控制台 |
| Webhook 重试和投递日志 | 新表 `webhook_deliveries`；失败按 1/5/30/120/600 秒退避重试 5 次；只保留最近 200 条；管理后台加“投递记录”和“重新发送” | 服务端、控制台 |
| Webhook 拒绝内网地址 | 投递前先解析 DNS，命中回环、私网、链路本地地址就拒绝；新增设置 `webhooks.allowPrivate`（默认关） | 服务端 |
| 数据保留期限 | 新增设置 `retention.*`（天数，0 表示永久）：通知 90、动态 365、聊天 0、审计 0、Webhook 投递 30；每小时清理一次；文档日志在快照之后清理到 `pruned_through` | 服务端、管理后台 |
| token 有效期 | OAuth 访问令牌单独用一个设置，默认 24 小时，Studio 到期前自动刷新；用密码登录拿到的 token 仍按原设置 | 服务端、Studio |
| 批注编辑和删除同步 | Studio 编辑、删除已发送的批注时调用 `comments.edit/delete`；收到线程事件时更新本地 | Studio |
| 资源请求自动关联 | Studio 导入资源时，如果有挂在那一行上、还没完成的资源请求，提示“这是对 X 的回应”，确认后执行 `todos.update {asset, status:"done"}`；控制台显示关联的缩略图 | Studio、控制台 |
| 评审者真正只读 | Studio 根据项目角色把编辑器切成只读 | Studio |
| 设备码登录界面 | Studio 添加服务器时可以选“用浏览器登录（设备码）”，显示用户码和链接 | Studio |

## 阶段 B：P1 看懂改动（全部在网页端计算）

- **修订对比**：新增路由 `/console/p/<id>/compare/<from>...<to>`。
  - 台词：按场景逐行对比，修改的行显示词级差异。
  - 蓝图：节点和连线的增、删、改。
  - 资源：图片左右并排或滑块对比，音频 A/B 试听。
- **变更明细**：tree 接口返回每个文件的内容哈希（由 Lore 给出，服务端不读文件内容），按哈希对比得出新增、删除、修改的文件，再归到场景、资源、蓝图。
- **引用分析**：资源详情里列出引用它的场景和行；另列“未使用的资源”。
- **剧本质检**：缺失资源、跳转目标不存在、变量没定义、角色没有立绘、某语言缺译文、术语没用规定译法（阶段 F 之后才有这一项）。新增路由 `/console/p/<id>/checks`，每条结果可以跳到对应行。

## 阶段 C：P2 审批与资源锁

- **审批状态**：新表 `approvals`，记录目标（场景或资源）、状态（`draft / pending / approved / changes`）、谁改的、备注；变更历史另存。
  - 方法：`approvals.list/set`，并有事件通知。
  - 评审者和所有者可以在控制台点“通过 / 打回”，打回必须写原因。这只改 Team 里的状态，不改项目内容。
- **里程碑门槛**：里程碑加 `dueAt` 和 `gate`（要求全部场景都已通过）；进度条显示通过比例。
- **资源锁**：新表 `asset_locks`，方法 `assets.lock/unlock/list`，有超时，管理员可以强制解锁。
  - Studio 改有锁的资源时提示并阻止。
  - 服务端在 `doc.intent` 改到被别人锁住的资源时拒绝。
- **待办标签和保存的筛选**：todo 加 `labels`；新表 `saved_filters`（按账号保存）。

## 阶段 D：P3 试玩与外部协作

- **试玩包**：新表 `builds`，文件存在 `<root>/builds/`。
  - 接口：HTTP `PUT /api/team/v1/projects/<id>/builds`（流式上传，有大小上限），`GET` 下载。
  - 方法：`builds.list/update/delete`，支持更新说明、关联的修订、标记“最新可玩版”。
  - 控制台加“试玩”标签页；Studio 导出构建后可以直接上传。
- **试玩内反馈**：Studio 试玩窗口里按快捷键提交，带上场景、台词 id 和截图，生成锚定在那一行的批注线程。截图走新的附件接口（`attachments`，同样存在 root 下）。
- **只读分享链接**：新表 `share_links`（存 token 哈希、范围、过期时间、是否允许批注、是否已吊销）。
  - 访问地址 `/console/s/<token>`，访问者是只读的访客身份，只能看到链接范围内的内容；所有访问写入审计。

## 阶段 E：P4 通知与参与感

- **PWA**：加 `manifest.webmanifest` 和 service worker（缓存外壳）。
- **Web Push**：服务端生成 VAPID 密钥，按 RFC 8291（aes128gcm）用 node:crypto 自己实现加密；新表 `push_subscriptions`。
- **邮件**：自己写 SMTP 客户端（node:net/tls，支持 STARTTLS 和 AUTH PLAIN/LOGIN），在管理后台配置。按每日或每周发摘要，也可以发到个人的飞书或 Slack 地址。
- **通知偏好**：新表 `notification_prefs`，按类型（提及、回复、指派、评审、关注）和渠道（站内、推送、邮件）分别开关。
- **关注**：新表 `watches`（项目或场景）；保存版本、改到所关注的场景时通知。
- **@提及自动补全**：控制台所有输入框都支持。
- **表情回应**：新表 `reactions`，可以回应批注和聊天消息。
- **项目讨论区**：锚点类型为 `project` 的线程。
- **时区和在线状态**：资料里加时区；头像显示对方当地时间和是否在线。

## 阶段 F：P5 本地化与配音 + P6 规划与统计

- **术语表**：新表 `glossary`（项目、原文、各语言规定译法、备注）。这是 Team 自己的数据，不是项目内容。
- **翻译记忆**：网页端从项目的本地化文件里检索相同或相近的原文，给出过去的译文。
- **翻译进度看板**：语言 × 场景矩阵。
- **配音**：按角色导出台本 CSV；新表 `voice_lines`，记录每句的录音状态（未录、已录、需重录）和关联的音频文件。
- **统计**：每个角色的句数和字数；剧本总字数、各场景字数、分支数、预估游玩时长。
- **燃尽图**：todo 加 `doneAt`，按里程碑画剩余待办曲线。
- **路线图**：里程碑放到时间轴上。
- **项目模板**：新表 `project_templates`，包含权限、里程碑和待办；创建项目时可以选一个套用。

## 阶段 G：P7 管理与安全

- **备份**：`nlteam backup` 命令和管理后台按钮都能用。
  - 用 SQLite 在线备份数据库，再把密钥和仓库打成 tar.gz（node 自己写 tar）。
  - 支持定时备份和保留份数。
  - 恢复只能用 `nlteam restore` 命令，而且要先停掉服务器。
  - 单个项目可以导出成 tar.gz。
- **两步验证**：TOTP（RFC 6238）加 10 个恢复码；管理员可以要求全员开启。
- **SSO**：
  - OIDC：授权码 + PKCE，用 JWKS 验证 id_token，按 email 或用户名匹配已有账号，也可以选择自动创建。
  - LDAP：只做 simple bind，自己写一个最小的 BER 编码。
- **密码重置**：管理员生成一次性链接，24 小时内有效。
- **审计日志**：可以按人、动作、时间筛选，并导出 CSV。
- **API token**：新表 `api_tokens`，按项目授权、限定权限、设过期时间，只保存哈希；用于脚本和机器人。
- **存储**：显示每个项目的占用；可以设配额，超过时拒绝上传试玩包和附件，接近上限时提醒。
- **项目归档和重命名**：归档后只读、默认隐藏，可以恢复。
- **IP 白名单**：设置 `security.allowedNetworks`（CIDR 列表），对网页控制台和 API 生效。

1. 运行 `npm run typecheck && npm run lint && npx vitest run`，新加的服务端功能都要有测试。

3. Studio 那边运行它自己的类型检查和相关测试。
